# HappiMynd Website

Front end for **HappiMynd** ("A Conscious Growth Ecosystem"). It has two parts that share one React app:

1. **Marketing site** (`/`, `/for-individuals`, `/for-organisations`, `/solv`, `/about`): static landing pages.
2. **User dashboard, "v2"** (`/v2/*`): login/signup, the HappiLIFE assessment, expert (psychologist) booking, plans and payments, resources, articles and support. It talks to the live HappiMynd Laravel backend at `https://happimynd.com`.

> **Repository note:** this is a **fork**. The original repository is
> **https://github.com/mayankkuthar/happy-mind-website**. Work is done on a fork and merged into the original through pull requests. See [Working with the fork](#working-with-the-fork).

## Getting started

```bash
git clone https://github.com/mayankkuthar/happy-mind-website.git   # or your fork
cd happy-mind-website
npm install
cp .env.example .env.local     # optional, all values have defaults
npm run dev                    # http://localhost:8080
```

- The dev server listens on **port 8080** on all interfaces (`host: "::"` in `vite.config.ts`).
- The **v2 dashboard calls the live production API (`https://happimynd.com`) by default.** Logging in locally uses real accounts and real OTPs, and payments create real Razorpay links. Point `VITE_AUTH_API_URL` / `VITE_HAPPILIFE_API_URL` at a staging backend if one exists.
- The marketing contact form uses same-origin paths (`/sanctum/csrf-cookie`, `/submit-contact`), which have no backend behind Vite. To make them work locally, start the dev server with the proxy enabled:

  ```bash
  VITE_DEV_API_PROXY=https://happimynd.com npm run dev
  ```

## Routing

Everything is declared in [src/App.tsx](src/App.tsx) using `BrowserRouter`. **New routes must be added above the `*` catch-all.**

| Path | Page | Auth |
|---|---|---|
| `/` | Marketing home | public |
| `/for-individuals`, `/for-organisations`, `/solv`, `/about` | Marketing pages | public |
| `/v2` | Dashboard home (`v2/pages/index.tsx`) | mixed |
| `/v2/login`, `/v2/signup` | OTP / password login, registration | public |
| `/v2/journey`, `/v2/profile`, `/v2/subscription`, `/v2/support` | User pages | protected |
| `/v2/assessment` | HappiLIFE assessment | protected |
| `/v2/experts` | Psychologist listing + HappiTALK booking | browse public, booking needs login |
| `/v2/services`, `/v2/services/:slug` | Plans / pricing per service (`happilife`, `solv`, …) | browse public, buying needs login |
| `/v2/cart`, `/v2/checkout/success` | Cart, post-payment landing | — |
| `/v2/resources`, `/v2/articles`, `/v2/articles/:slug`, `/v2/games`, `/v2/quizzard` | Content | public |
| `*` | NotFound | — |

- Marketing pages get the floating contact button, mascot intro and welcome audio (`GlobalChrome`). `/v2` pages get `V2Layout`, which adds the contact widget, v2 toasts and background audio.
- Inside v2, use `V2Link` / `useV2Navigate` from `src/v2/lib/router.tsx` and write paths **without** `/v2` (for example `to: "/login"`). The helper adds the prefix.
- Login redirects use `?redirect=/v2/...`. Only paths that start with `/` are honoured.
- `/v2/quizzard` and the games link to the external app `https://quizzard.happimynd.com/`.

## How it works

### Authentication

There are two auth mechanisms in the codebase. **Only the first is used by the live v2 dashboard.**

**1. Bearer-token auth (v2, active)**
- `/v2/login` supports **mobile OTP** (`send-login-otp` → `verify-login-otp`) and **username + password** (`/api/v1/login`). Country code defaults to `91`.
- `verify-login-otp` returns one of three things:
  - `success` + `access_token`: the user is signed in.
  - `register` + `mobile_verified_token`: the user is sent to `/v2/signup` to finish registration.
  - `error`.
- On success, `auth.signIn({ name, email, token, avatar })` stores the user in **`localStorage["happimynd_auth_v1"]`** and fires a `happimynd:auth-change` event. Every API helper reads `auth.get()?.token` and sends `Authorization: Bearer <token>`.
- `signIn` and `signOut` call `queryClient.clear()`. React Query keys are not scoped per user, so without this a second account on the same browser would see the first account's cached data.
- Protected pages call `useProtectedRoute()`, which redirects to `/v2/login?redirect=<current path>` once auth state has loaded from storage.
- Signup sends `signup_type: "organization"` for the Organization/School categories plus an optional `happimyndCode` (sponsor code). The backend expects the spelling **"organization"** (with a z).

**2. Sanctum cookie session (legacy, not wired up)**
- `src/lib/happimyndAuth.ts` and `src/components/BookSessionModal.tsx` read the Laravel session cookie via `/api/user`. `BookSessionModal` is **not imported anywhere** and is left over from an earlier design.

### API clients and CSRF

- `src/v2/lib/website-api.ts`, `auth-api.ts` and `assessment/client.ts` are thin `fetch` wrappers. They unwrap Laravel's `{ data: ... }` envelope and are tolerant of several response shapes.
- Every request goes through `fetchWithCsrf()` ([src/v2/lib/csrf.ts](src/v2/lib/csrf.ts)). It sends the request as-is first. If the response is **419 (CSRF token mismatch)**, it fetches `/sanctum/csrf-cookie` (with `/api/v1/csrf-cookie` and `/csrf-cookie` as fallbacks), then retries with `credentials: "include"` and the `X-XSRF-TOKEN` header.
- In development, `website-api.ts` logs every request and response to the console as `🌐 [Website API] ...`, and `useOrgStatus` logs `🏢 [useOrgStatus] ...`. Use these logs first when debugging.

### Organisation (B2B) users

[src/v2/hooks/use-org-status.ts](src/v2/hooks/use-org-status.ts) decides whether the user is sponsored by an organisation. It checks **`organization_plan_ids`** from `GET /api/v1/website/subscribed-services`. It does not use `happimynd_code`, because that field is unreliable on the backend.

| Constant | Plan ID | Meaning |
|---|---|---|
| `HAPPILIFE_SCREENING` | 1 | HappiLIFE screening |
| `HAPPILIFE_SUMMARY` | 2 | HappiLIFE summary |
| `HAPPIBUDDY` | 3 | HappiBUDDY |
| `HAPPITALK` | 6 | Corporate HappiTALK (psychologist sessions) |
| `HAPPISELF` | 21 | HappiSELF |
| `SOLV` | 22 | SOLV, shown as **"HappiGUIDE"** to org users |

For an org user:
- **SOLV is renamed to HappiGUIDE** throughout the UI.
- Services covered by the org are booked for **₹0** through the `avail-*` endpoints, with no Razorpay step.
- `/v2/experts` passes the token so the backend returns only the org's psychologist panel.
- The pricing table on `/v2/services/:slug` is blurred, because the plans are already provided.

If plan IDs change on the backend, update `ORG_PLAN_IDS`.

### Booking a session

`BookSessionDialog` ([src/v2/components/book-session-dialog.tsx](src/v2/components/book-session-dialog.tsx)) is the single booking UI. It is used from the dashboard, experts, services and resources pages.

1. The user picks a service (HappiTALK or SOLV/HappiGUIDE) and **two preferred date and slot choices**. Slots are one hour long and start every 30 minutes (`TIME_SLOTS`).
2. A guest who is not logged in has the form saved with `savePendingBooking()` and `markBookingResume()`, then goes to login. When the page loads again, `consumeBookingResume()` reopens the dialog with the saved slots.
3. What happens on submit depends on the user:
   - **Org-covered:** `POST /api/v1/avail-haapitalk-user` (backend spelling) or `/avail-happiguide-user`. This creates a B2B ₹0 booking.
   - **100% coupon:** `POST /api/v1/avail-free-services`.
   - **Paid:** `POST /api/v1/payment-for-happitalk` or `/payment-for-happiguide`. The response contains `{ link }`, and the browser navigates to that Razorpay link.

### Payments, coupons and GST

- Plans come from `GET /api/v1/packages`. Displayed prices are **exclusive of 18% GST**.
- **The front end adds GST:** `payForBundle`, `payForHappiTalk` and `payForHappiGuide` send `amount: Math.round(amount * 1.18)`. The breakdown modals show the same calculation. If the backend ever starts adding GST itself, remove the `* 1.18` or customers will be charged GST twice.
- Coupons: `POST /api/v1/apply-coupon` returns `coupon_id` and `discount`. The same value is sent as `coupen_id` **and** `coupon_id`, because the backend uses the misspelling `coupen` in some places. A 100% discount goes through `avail-free-services` instead of Razorpay.
- After payment, Razorpay or the backend redirects to `/v2/checkout/success?status=...`. That page re-fetches `subscribed-services` to confirm the purchase. `status=failed|cancelled` shows the failure state.
- `/v2/cart` stores items in `localStorage`. Each bundle is still paid for separately through `/api/v1/payment`.

### HappiLIFE assessment

- Endpoints are wrapped in [src/v2/lib/assessment/api.ts](src/v2/lib/assessment/api.ts): `checkifany`, `start-assessment` (always sends `platform: "mobile"`), `save-option`, `update-last-answer`, `complete-assessment`, `assessment-status`, `view-report`, `get-report` and `get-all-report`. All are POST requests with a Bearer token.
- Each answer is saved as soon as it is selected. Only the **last** answer can be changed (`update-last-answer`).
- `useAssessmentPhase()` returns `not-started`, `in-progress` or `completed` plus progress. "Has a report" comes from `get-all-report`, because `checkifany` only describes the latest attempt. The backend allows up to **6 attempts** per user.

### Contact forms

- **Marketing site:** `ContactFormModal` (opened from `FloatingContactButton`) does a **same-origin** Sanctum handshake (`GET /sanctum/csrf-cookie`), then `POST /submit-contact`. On Vercel, both paths are rewritten to `happimynd.com`, so the site works when hosted on another domain.
- **v2:** `ContactUsWidget` posts to `POST /api/v1/submit-contact`. Logged-in users raise tickets on `/v2/support` through `POST /api/v1/website/raise-query`.

### Background audio and mascot

- `WelcomeAudio` (marketing) and `GlobalBackgroundAudio` (v2) play `calm-morning.mp3` for **30 seconds total** with a fade-out, and the user can mute it. Browsers block autoplay until the user interacts with the page, so playback starts on the first click or tap.
- `MascotIntro` shows the animated mascot on the marketing pages.

### Browser storage keys

| Key | Storage | Purpose |
|---|---|---|
| `happimynd_auth_v1` | localStorage | Signed-in user + Bearer token |
| `happimynd_user_avatar_v1` (+ per-user avatar keys) | localStorage | Chosen avatar |
| `happimynd_pending_booking_v1` | local + session | Booking form saved across login |
| `happimynd:booking-resume-v2` | local + session | "Reopen booking dialog after login" flag |
| `happimynd_cart_v1` | localStorage | Cart items |
| `happimynd_bookings_v1`, `happimynd_contact_queries_v1` | localStorage | Local-only logs (not sent anywhere) |

## Deployment

The site is deployed on **Vercel** using [vercel.json](vercel.json):

- Build: `npm install` → `npm run build` → serve `dist/`.
- Rewrites:
  - `/sanctum/*` and `/submit-contact` → `https://happimynd.com/...` (marketing contact form).
  - Everything else → `/index.html`. This SPA fallback lets deep links such as `/v2/experts` load.
- Set any `VITE_*` variables in **Vercel → Project → Settings → Environment Variables**, then **redeploy**. They are read at build time.
- Hosting somewhere else (Nginx, Netlify, inside Laravel) needs the same two things: an SPA fallback to `index.html`, and either a proxy for `/sanctum` and `/submit-contact` or hosting on the same domain as the backend.
- When adding public pages, update `public/sitemap.xml` and `public/robots.txt`.

`dist/` is git-ignored. Never commit build output.

## Troubleshooting

### Setup and build

| Symptom | Cause | Fix |
|---|---|---|
| `npm install` fails with peer-dependency errors (`ERESOLVE`) | Newer npm is stricter with peer ranges | `npm install --legacy-peer-deps`, or delete `node_modules` and run `npm ci` so the lockfile is used exactly. |
| `SyntaxError` / unsupported engine on `npm run dev` | Node version is too old | Use Node 18+ (20/22 LTS recommended). `node -v` to check. Use `nvm install 20 && nvm use 20`. |
| `Port 8080 is in use` | Another process is on 8080 | `lsof -i :8080` and kill the process, or run `npm run dev -- --port 5173`. |
| Build warning: "Some chunks are larger than 500 kB" | The whole app is one bundle, and images/MP3s are large | Only a warning, the build succeeds. To fix, lazy-load v2 pages with `React.lazy` and compress assets. |
| `Failed to resolve import "@/..."` | Wrong path or file renamed | `@` maps to `src/`. Check file-name case: macOS ignores case but Vercel (Linux) does not, so a case mismatch can work locally and fail on deploy. |
| Image works locally, broken on Vercel | Case mismatch, or the file was never committed | Check `git ls-files src/assets` and match the case exactly. File names with spaces (for example `SOLV-Hero Section-left side.png`) work but are fragile. Prefer kebab-case. |
| `npm run lint` shows ~134 errors | These problems already exist in the codebase (`no-explicit-any`, a `require()` in `tailwind.config.ts`, etc.) | Not a blocker. Compare against the baseline and make sure your change does not add new errors. |
| Env change has no effect | `VITE_*` values are compiled in at build time | Restart `npm run dev`, or redeploy on Vercel after changing the value. |
| `VITE_DEV_API_PROXY` in `.env` does nothing | `vite.config.ts` reads it from `process.env`, which Vite does not populate from `.env` | Pass it in the shell: `VITE_DEV_API_PROXY=https://happimynd.com npm run dev`. |

### Runtime / API

| Symptom | Cause | Fix |
|---|---|---|
| Console: **CORS error** / `TypeError: Failed to fetch` on `/api/v1/...` | The browser calls `https://happimynd.com` directly from another origin (localhost, a preview URL) | The backend's CORS config (`config/cors.php`) must allow that origin. Ask the backend owner to add the domain, or proxy `/api` and set `VITE_AUTH_API_URL` to the same origin. |
| **419 "CSRF token mismatch — please refresh the page"** | Laravel CSRF protection on a route | `fetchWithCsrf` retries automatically, but the retry only works if the API allows credentialed CORS (`supports_credentials: true` + an explicit origin). Refresh the page, or clear cookies for happimynd.com. |
| Marketing contact form fails locally (HTML response / "Unexpected token <") | `/sanctum/csrf-cookie` and `/submit-contact` hit Vite, which returns `index.html` | Run with `VITE_DEV_API_PROXY=https://happimynd.com`. In production, check that the `vercel.json` rewrites are present. |
| OTP never arrives | Wrong number format, rate limit or backend SMS issue | Enter a 10-digit number without `+91`. Wait before resending. Check the `send-login-otp` response in the Network tab. Otherwise ask the backend team to check the SMS provider. |
| Login succeeds but the user is logged out immediately / API returns 401 | Token expired or revoked, or localStorage is blocked (private mode) | Log out and log in again. Clear `happimynd_auth_v1`. Avoid strict private browsing. |
| Wrong account's data after switching users | Old React Query cache | Should be handled by `queryClient.clear()` on sign-in/out. If it still happens, hard-reload. When adding queries, include the token or user in the `queryKey`. |
| Org user sees prices / SOLV instead of HappiGUIDE / is asked to pay | `organization_plan_ids` is empty or the request failed | In dev, check the `🏢 [useOrgStatus]` console log. Confirm with the backend that the user's org has plan IDs 6/22 provisioned. Check that `ORG_PLAN_IDS` matches the backend. |
| Org expert list is empty or shows the public panel | Token not sent, or no psychologists assigned to the org | Check that the `Authorization` header is on `/website/psychologists`. Assign psychologists to the org in the backend admin. |
| SOLV/HappiGUIDE payment fails with a "psychologist" error | No psychologist is assigned to the HappiGuide plan in the backend admin | Assign one in the admin panel (backend config, not a front-end bug). |
| "Slot already booked" / HappiTALK payment rejected | The backend validates slot availability | Pick another slot. This is expected behaviour. |
| Charged amount is 18% higher than expected, or GST appears twice | The front end adds GST (`* 1.18`) before calling the payment API | Check whether the backend also adds GST. Exactly one side should add it (see [Payments](#payments-coupons-and-gst)). |
| Coupon is rejected even though it is valid | Coupon belongs to a different `plan_id`, or the backend field name changed | Check the `apply-coupon` request/response. The front end sends `coupon`, `coupon_code` and `coupen`. |
| After payment the success page shows but the plan is not active | Razorpay webhook/callback delay on the backend | Refresh `/v2/subscription` after a minute. If it still isn't active, check the payment in the Razorpay dashboard and the backend logs. |
| Booking dialog does not reopen after login | Resume flag was lost (storage blocked or cleared) | The user can open "Book a session" again. Check `happimynd:booking-resume-v2` in storage. |
| Assessment shows the previous attempt or wrong progress | Cached `assessment` queries / `localStorage` keys | Hard-reload or clear site data. The backend caps attempts at 6, after which retakes are blocked. |
| Background music doesn't play | Browser autoplay policy | Expected. It starts after the first click. It stops on its own after 30 seconds. |
| Refreshing `/v2/...` gives a 404 on the host | The host has no SPA fallback | Add a rewrite of all paths to `/index.html` (already in `vercel.json` for Vercel). |
| Blank white page in production | Runtime JS error | Open DevTools → Console. Run `npm run build && npm run preview` locally to reproduce. |

### General debugging tips

- **Network tab** in DevTools: every v2 call goes to `/api/v1/...`. Check the status code (401 = auth, 419 = CSRF, 422 = validation, 5xx = backend) and the JSON `message`.
- In `npm run dev`, all Website API calls are logged to the console with their responses.
- Most "stuck" UI states are fixed by clearing site data (localStorage + sessionStorage + cookies) for the site.

## Known issues and tech debt

- **ESLint has about 134 existing problems.** TypeScript runs in non-strict mode (`strict: false`, `noImplicitAny: false`).
- **No automated tests.**
- **One large JS bundle (~1.3 MB, ~360 kB gzipped)** and several multi-MB images and MP3s. Route-level code splitting and image compression would improve load time.
- **Duplicate code:** two shadcn/ui kits (`src/components/ui` and `src/v2/components/ui`), and two `bookings.ts` files (`src/lib` and `src/v2/lib`).
- **Unused legacy code:** `src/components/BookSessionModal.tsx` and `src/lib/happimyndAuth.ts` (Sanctum cookie session) are not used by any route. `src/v2/lib/error-capture.ts`, `error-page.ts` and `lovable-error-reporting.ts` are leftovers from the Lovable template.
- `src/v2/assets/*.asset.json` files are Lovable asset pointers (`/__l5e/assets-v1/...`). The app imports the real image files instead, so these JSON files are unused.
- The Open Graph/Twitter image in `index.html` still points at a Lovable placeholder (`lovable.dev/opengraph-image-...`). Replace it with a HappiMynd image.
- `useUserProfile` falls back to placeholder data (`Guest User`, `+91 98765 43210`) when there is no token.
- The `/api/v1/login` and `/api/v1/edit-profile` field names were not fully confirmed against the backend (see the comment at the top of `auth-api.ts`).
- Backend spellings that must not be "fixed" on the front end alone: `avail-haapitalk-user`, `coupen_id`.
- The auth token is stored in `localStorage`, which XSS can read. Avoid `dangerouslySetInnerHTML` with untrusted content.
